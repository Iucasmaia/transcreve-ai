# Internationalization

Seven locales: `en`, `pt-BR`, `pt-PT`, `es`, `fr`, `it`, `ru`. English is the source of
truth: `src/shared/i18n/locales/en.ts` defines the keys and
`src/shared/i18n/types.ts` derives `LocaleMessages` and `MessageKey` from it. Every
other locale is declared with `satisfies LocaleMessages`, so a missing or extra key is a
type error before it can reach a validator.

## Detection

`src/shared/i18n/detect.ts` implements the rules:

| Browser language | Locale |
|---|---|
| `pt-BR`, `pt_BR`, anything with `br` | `pt-BR` |
| other `pt*` (`pt`, `pt-PT`, `pt-AO`) | `pt-PT` |
| `es*`, `fr*`, `it*`, `ru*` | the matching locale |
| anything else | `en` |

`resolveLocale` returns the stored locale when the setting is not `auto`, otherwise the
detected one. `setLanguage` resolves once per context and caches the result; `getLocale`
returns the active locale.

## Runtime API

- `t(key, vars?)` interpolates `{name}` placeholders, replacing every occurrence and
  leaving unknown placeholders untouched. A key missing from the active locale falls
  back to English, and an unknown key returns the key itself.
- `applyToDom(root)` walks `[data-i18n]` elements and sets their `textContent`, skipping
  attributes whose value is not a known key.
- `locales()` and `localeDisplayName(id)` feed the UI language selector.

The module reads `navigator.languages` when it exists and degrades gracefully in a
service worker or in jsdom, where `navigator` may be missing.

## Manifest strings

Extension name, description and action title cannot be read from `storage`: the browser
needs them at install time through `_locales`. `src/shared/i18n/manifest-strings.ts`
holds those three strings per locale, and `scripts/manifest.ts` writes
`_locales/<dir>/messages.json` for each target, mapping the locale id to the Chrome
directory name (`pt-BR` to `pt_BR`, and so on). That removes the previous duplication
between the panel translations and the manifest locales.

## Rules

- Every user-facing string goes through `t`; no literal UI text in the code.
- New keys are added to `en` first, then to all seven locales in the same change.
- `yarn validate:i18n` fails on key drift between locales and on unknown keys used in
  `t("...")` calls or `data-i18n` attributes.
